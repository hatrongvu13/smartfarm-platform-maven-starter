# V3.7 End-to-End Scenarios

## Scenario A — Heating

1. [ ] Simulator reports low temperature.
2. [ ] MQTT ingestion accepts telemetry.
3. [ ] Rule engine evaluates threshold.
4. [ ] Heater command is issued.
5. [ ] Device acknowledges.
6. [ ] State becomes ON.
7. [ ] Audit is written.
8. [ ] Temperature returns above upper threshold.
9. [ ] Heater turns OFF.

## Scenario B — Humidity

1. [ ] Humidity rises.
2. [ ] Rule enters pending duration.
3. [ ] Threshold persists.
4. [ ] Fan turns ON.
5. [ ] Humidity decreases.
6. [ ] Hysteresis prevents rapid toggling.
7. [ ] Fan turns OFF.

## Scenario C — Gas

1. [ ] Gas concentration exceeds configured safety threshold.
2. [ ] Rule triggers ventilation.
3. [ ] Alert is generated.
4. [ ] Operator sees current device state.
5. [ ] Fan acknowledgement is verified.

## Scenario D — Failure

1. [ ] Sensor stops publishing.
2. [ ] Stale telemetry is detected.
3. [ ] Automation enters configured safe behavior.
4. [ ] Operator receives alert.
5. [ ] Sensor reconnects.
6. [ ] Automation resumes only after configured validation.
